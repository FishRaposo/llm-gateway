What was wrong, and what changed

F1 · HIGH

Default admin credential accepted in any deployment

The admin key defaulted to a value printed in the source tree, and nothing stopped that default outside test mode — a deploy that forgot one variable served open admin access.

Fixed. Config load now refuses to start when the key is unset or still the default. Three production-mode tests were updated to prove the guard fires.

src/config.ts · tests/l1Audit.test.ts (F1 block, 4 cases)

F2 · HIGH

Unvalidated request fields, and tool messages dropped in silence

Model, temperature and max_tokens were never type-checked, so negatives and unbounded integers reached the provider and the budget estimate. Tool-role messages were filtered out before the model saw them: a conversation answered on half its context, with no signal.

Fixed. Fields are validated with named errors; tool and function roles are rejected explicitly rather than forwarded half-formed, and the silent filter is gone.

F3 · HIGH

Budget admission reserved input cost only

Reservations priced the prompt and ignored the output the request could produce, so a single call could overrun a per-key budget several orders of magnitude past its reservation — the exact exposure the gateway exists to prevent.

Fixed. The estimate now adds a bounded worst case derived from the model catalog, clamped to its output ceiling; settlement still records actual spend.

Checked and cleared

  • Cross-tenant cache: keys scoped to the account identity, auth runs before cache
  • Rate-limit identity: canonical account id after auth; plaintext fallback unreachable for valid requests
  • Audit credential storage: raw keys masked before persist and on read
  • Fallback and streaming: retryable-aware, allowlisted, circuit broken
  • Budget lifecycle: atomic reserve/settle/release with request idempotency
  • Admin routes: bootstrap key or stored permission; key creation enforces a budget
